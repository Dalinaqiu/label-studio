# Label Studio 前端 UI 改造方案（中国大陆用户导向）

## 文档目标

本文档用于指导 `web/apps/labelstudio` 主应用的前端 UI 改版，目标不是做一次纯视觉翻新，而是完成以下三件事：

- 统一现有新旧页面混用的视觉和交互语言
- 提升中国大陆用户在项目管理、任务处理、设置配置场景下的使用效率
- 明确 `web/apps/labelstudio` 与 `web/libs/ui` 的边界，形成可分阶段落地的组件改造路线

改造原则如下：

- 面向专业工具型后台，而不是营销型 SaaS 页面
- 信息密度中高，但主次明确
- 主操作显性，弱化“藏在 hover 和三点菜单里”的交互
- 中文语境优先，文案、状态、时间格式、排版节奏都按中国大陆用户习惯处理
- 页面优先收敛到统一壳层、统一标题区、统一列表和表单规范，再逐步处理复杂业务模块

---

## 1. 页面级改版清单

本节按页面分组列出改造目标、问题、改造方向、涉及目录。

### 1.1 全局壳层与导航

涉及目录：

- `web/apps/labelstudio/src/app`
- `web/apps/labelstudio/src/components/Menubar`
- `web/apps/labelstudio/src/components/Breadcrumbs`
- `web/apps/labelstudio/src/components/SidebarMenu`
- `web/apps/labelstudio/src/themes/default`

现状问题：

- 顶部导航、侧边导航、页面内容区整体结构已经成型，但不同页面的标题区、按钮区、面包屑区不一致
- 首页与业务页风格差异明显，造成“像两个产品”的感受
- 导航入口对中国大陆用户来说略偏抽象，主操作在部分页面不够显眼

改造目标：

- 统一全局壳层为“顶部全局栏 + 左侧主导航 + 内容工作区”
- 一级导航文案更动作化、更符合企业工具习惯
- 页面标题区统一成标准结构：标题、描述、筛选/辅助信息、主操作区
- 面包屑层级缩短，避免冗长路径

改造建议：

- 一级导航调整为：
  - 工作台
  - 项目管理
  - 数据任务
  - 团队与组织
  - 模型与预测
  - 系统设置
- 顶栏右侧保留账户、快捷帮助、主题能力，但弱化无关入口
- 面包屑只保留 2 到 3 级，不显示重复节点
- 所有页面共用统一 `PageHeader` 组件，禁止各页面单独拼标题区

优先级：P0

---

### 1.2 首页改版为“工作台”

涉及目录：

- `web/apps/labelstudio/src/pages/Home`

现状问题：

- 当前首页更接近轻量欢迎页，信息密度偏低
- 右侧区块被注释后，页面视觉重心偏左
- 对中国大陆用户来说，进入系统后缺少“先看数据、再做动作”的工作台体验

改造目标：

- 首页承担“默认起点页”角色
- 用户进入后可以快速看到项目、任务、成员、近期待办
- 首页内容以效率为导向，而不是以欢迎语为导向

改造方案：

- 顶部增加概览卡
  - 项目总数
  - 待标注任务数
  - 近 7 日提交量
  - 活跃成员数
- 增加快捷操作区
  - 新建项目
  - 导入数据
  - 继续标注
  - 邀请成员
- 最近项目区从纯卡片列表升级为“紧凑列表卡片”
  - 项目名称
  - 当前状态
  - 任务进度
  - 最近更新时间
  - 直接进入“数据管理 / 标注 / 设置”
- 右侧补充系统通知与帮助入口
  - 版本更新
  - 使用帮助
  - 新手引导

适配中国大陆用户的设计要点：

- 默认展示关键数字，不把运营信息藏深
- 快捷操作用动词短语，如“新建项目”“导入数据”
- 最近项目支持更高信息密度，不只展示标题

优先级：P0

---

### 1.3 项目列表页改为“表格优先，卡片为辅”

涉及目录：

- `web/apps/labelstudio/src/pages/Projects`

现状问题：

- 当前项目列表主要是卡片墙，浏览可以，管理效率一般
- 顶部缺少标准筛选区和搜索区
- 关键操作依赖卡片内部点击和三点菜单，不利于高频管理

改造目标：

- 让项目列表成为真正的项目管理中心
- 默认视图适合批量查看、搜索、筛选、排序
- 同时保留卡片视图作为补充浏览模式

改造方案：

- 默认视图改为表格视图
- 增加“表格视图 / 卡片视图”切换
- 顶部筛选栏包含：
  - 搜索框
  - 状态筛选
  - 成员筛选
  - 时间排序
  - 新建项目按钮
- 表格字段建议：
  - 项目名称
  - 项目类型
  - 任务数
  - 已完成
  - 进度
  - 负责人
  - 最近更新时间
  - 状态
  - 操作
- 操作列至少提供：
  - 进入数据管理
  - 开始标注
  - 项目设置
  - 更多
- 保留卡片视图，但改成更紧凑的信息卡，而不是大面积留白卡

适配中国大陆用户的设计要点：

- 默认优先表格，因为更符合后台使用习惯
- 进度列要明确显示数值与百分比
- 批量操作入口应可见，不能过深

优先级：P0

### 1.4 创建项目页重构为标准向导

涉及目录：

- `web/apps/labelstudio/src/pages/CreateProject`

现状问题：

- 当前采用全屏弹窗 + tab 切换，流程感弱
- 用户可能不知道当前已经完成哪一步、下一步是什么
- 配置、导入、名称编辑在一个容器里，层次感不足

改造目标：

- 将创建项目改为明确的 4 步向导
- 每一步只聚焦当前任务
- 让新用户和中国大陆企业用户都能快速理解流程

改造方案：

步骤结构：

1. 基本信息
2. 导入数据
3. 标注模板
4. 确认创建

每一步的改造重点：

- 基本信息
  - 项目名称
  - 项目描述
  - 项目类型
  - 工作区归属
- 导入数据
  - 本地上传
  - 云存储导入
  - 示例数据
  - 导入结果反馈
- 标注模板
  - 模板推荐
  - 自定义配置
  - 预览区
- 确认创建
  - 信息摘要
  - 数据量摘要
  - 模板摘要
  - 创建后默认进入数据管理

适配中国大陆用户的设计要点：

- 向导按钮使用“上一步 / 下一步 / 创建项目”
- 必填项明确显示
- 失败和校验错误必须就地提示
- 导入结束后显示“成功多少 / 失败多少 / 下一步建议”

优先级：P0

---

### 1.5 数据管理页升级为“任务处理台”

涉及目录：

- `web/apps/labelstudio/src/pages/DataManager`
- `web/libs/datamanager`（若后续联动）
- `web/libs/editor`（若后续联动）

现状问题：

- 当前数据管理页更像容器页，外层壳与内部能力衔接较弱
- 模式切换、任务状态、批量操作、上下文信息不够集中
- 对高频处理用户来说，缺少稳定的操作节奏

改造目标：

- 将数据管理页定义为“任务处理台”
- 强化顶部任务信息区、筛选区、操作区
- 让用户始终知道“当前在哪个项目、哪类任务、还能做什么”

改造方案：

- 顶部固定任务栏
  - 项目名称
  - 当前筛选条件
  - 当前任务位置
  - 保存、提交、跳过、上一条、下一条
- 左侧增强筛选面板
  - 任务状态
  - 标注成员
  - 数据来源
  - 时间范围
- 列表区和标注区切换逻辑更显性
- AI 预测相关能力加上标识
  - 预测来源
  - 置信度
  - 是否人工确认

适配中国大陆用户的设计要点：

- 操作按钮固定可见，不依赖 hover
- 状态字段短且稳定，如“未开始”“进行中”“已完成”“已跳过”
- 批量入口可见，避免深层菜单

优先级：P1

---

### 1.6 设置页与组织页统一成标准后台布局

涉及目录：

- `web/apps/labelstudio/src/pages/Settings`
- `web/apps/labelstudio/src/pages/Organization`
- `web/apps/labelstudio/src/components/SidebarMenu`

现状问题：

- 设置页与组织页已有侧边栏模式，但视觉和内容组织仍偏旧
- 表单、列表、说明文案样式不完全统一
- 存储、模型、成员、标注设置的复杂度高，但页面表达层次不够清晰

改造目标：

- 统一为“左侧二级导航 + 右侧内容区 + 页面说明 + 主操作”
- 复杂设置页按“概览 / 列表 / 详情 / 表单”结构组织

改造方案：

- 所有设置页统一引入 `PageHeader`
- 为复杂设置页增加摘要卡
  - 当前已接入几个存储
  - 当前已配置几个模型
  - 默认策略是什么
- 列表与表单统一宽度、间距、字段说明方式
- 危险操作单独沉到底部危险区

适配中国大陆用户的设计要点：

- 复杂设置页优先给结论和状态，再给说明
- 帮助文案不宜过长，必要时折叠
- 危险操作要有明显视觉隔离

优先级：P1

---

### 1.7 空状态、错误状态、反馈体系统一

涉及目录：

- `web/apps/labelstudio/src/components/EmptyState`
- `web/apps/labelstudio/src/components/Error`
- `web/libs/ui`

现状问题：

- 空状态表现不一致，有的偏插画化，有的偏纯文本
- 错误提示和成功反馈缺少统一设计语言

改造目标：

- 统一空状态、加载状态、错误状态、成功反馈
- 所有反馈均同时说明“发生了什么”和“下一步怎么做”

改造方案：

- 空状态统一结构：
  - 图标或插图
  - 标题
  - 一句话说明
  - 主操作按钮
  - 次操作链接
- 错误状态统一结构：
  - 错误标题
  - 原因说明
  - 重试按钮
  - 返回上一级按钮
- Toast 规则统一：
  - 成功类短提示
  - 失败类提示带动作建议

优先级：P1

## 3. 适合这个仓库的组件改造路线

本节直接对应仓库结构，明确哪些能力应收敛到 `web/libs/ui`，哪些能力保留在 `web/apps/labelstudio`。

### 3.1 拆分原则

`web/libs/ui` 负责：

- 纯展示型基础组件
- 与具体业务无关的复合后台组件
- 设计 token、布局规范、交互模式规范

`web/apps/labelstudio` 负责：

- 业务页面
- 业务容器组件
- 路由拼装
- API 数据获取与状态组合
- 与项目、任务、组织、标注等业务强绑定的组件

判断标准：

- 如果一个组件离开 Label Studio 业务后仍可复用，放到 `web/libs/ui`
- 如果组件内部带强业务词汇、业务接口、业务规则，留在 `web/apps/labelstudio`

---

### 3.2 第一阶段：先补齐 UI 骨架组件

目标：

- 先统一页面骨架，再谈业务重构

建议新增到 `web/libs/ui` 的组件：

- `PageHeader`
  - 标题
  - 描述
  - extra 操作区
  - breadcrumb slot
- `PageSection`
  - 区块标题
  - 区块描述
  - 右侧附加动作
- `StatCard`
  - 标题
  - 数值
  - 同比/趋势
  - 附加说明
- `FilterBar`
  - 搜索框
  - Select 筛选
  - 日期筛选
  - 视图切换
  - 操作按钮区
- `EmptyState`
  - 图标
  - 标题
  - 描述
  - 主次操作
- `ResultState`
  - 成功 / 失败 / 无权限 / 无数据 / 网络错误
- `ActionBar`
  - 页面级主操作
  - 列表批量操作

建议保留在 `web/apps/labelstudio` 的页面整合层：

- 首页工作台容器
- 项目列表容器
- 创建项目步骤容器
- 数据管理页容器
- 设置页容器

建议目录结构：

- `web/libs/ui/src/components/layout/PageHeader`
- `web/libs/ui/src/components/layout/PageSection`
- `web/libs/ui/src/components/feedback/EmptyState`
- `web/libs/ui/src/components/feedback/ResultState`
- `web/libs/ui/src/components/data-display/StatCard`
- `web/libs/ui/src/components/data-entry/FilterBar`
- `web/libs/ui/src/components/navigation/ActionBar`

---

### 3.3 第二阶段：收敛列表、表单、向导能力

目标：

- 让项目页、设置页、导入页、组织页共享同一套模式

建议新增到 `web/libs/ui` 的复合组件：

- `DataTableShell`
  - 表头区
  - 筛选区
  - 表格区
  - 分页区
- `ResourceCard`
  - 用于卡片模式的项目、存储、模型等资源展示
- `WizardLayout`
  - 步骤条
  - 内容区
  - 底部操作区
- `SettingsLayout`
  - 左侧二级导航
  - 右侧内容区
  - 顶部摘要区
- `FormSection`
  - 分组标题
  - 字段说明
  - 内容容器
- `InlineHelp`
  - 短说明
  - Tooltip
  - 文档跳转

对应迁移建议：

- `Projects` 页面切到 `DataTableShell`
- `CreateProject` 页面切到 `WizardLayout`
- `Settings` 和 `Organization` 页面切到 `SettingsLayout`
- 存储设置、模型设置、成员设置切到 `FormSection`

### 3.4 第三阶段：统一状态、文案、视觉 token

目标：

- 解决“新旧视觉并存”和“中文语义不一致”的问题

建议在 `web/libs/ui` 中统一处理：

- 中文优先字体栈
- 标题字号体系
- 表单标签和帮助文案样式
- 状态颜色与状态标签
- 时间格式展示工具
- 页面留白、区块间距、容器宽度 token

建议改造文件：

- `web/apps/labelstudio/src/themes/default/typography.scss`
- `web/apps/labelstudio/src/themes/default/colors.scss`
- `web/apps/labelstudio/src/themes/default/tokens.scss`
- `web/libs/ui/src/tokens/*`

建议新增 token 维度：

- `page-max-width`
- `page-padding-x`
- `page-padding-y`
- `section-gap`
- `toolbar-height`
- `table-row-height`
- `compact-density`
- `default-density`

文案规则建议沉淀为前端约定：

- 按钮优先使用动词
- 状态优先使用两到四字短语
- 提示先说结果，再说动作
- 时间格式默认 `YYYY-MM-DD HH:mm`

### 3.6 建议的落地顺序

第一批，2 周内可启动：

- 补 `PageHeader`、`StatCard`、`FilterBar`、`EmptyState`
- 首页改工作台
- 项目列表加表格视图和筛选栏

第二批，2 到 4 周：

- `WizardLayout` 落地
- 创建项目向导重构
- 设置页和组织页统一页头和侧栏布局

第三批，4 周以后：

- 数据管理页外层工作台化
- 状态、反馈、文案、token 全量收敛
- 逐步替换遗留 BEM 页面样式
