# Label Studio 前端 UI 页面验收 Checklist

## 文档说明

本文档用于配合以下文档进行页面改版验收：

- [frontend-ui-redesign-plan-cn.md](/Users/nengli/projects/py_projects/label-studio/docs/frontend-ui-redesign-plan-cn.md)

适用场景：

- 页面改版开发自检
- 提测前验收
- 联调走查
- 产品和设计联合验收

建议使用方式：

- 每个页面单独过一遍“通用验收项”
- 再过对应页面的“专项验收项”

建议结果标记：

- `通过`
- `需调整`
- `不适用`

## 1. 通用验收项

以下项适用于所有改版页面。

### 1.1 页面结构与首屏认知

- [ ] 页面标题清晰，用户进入后 5 秒内能理解页面用途
- [ ] 页面标题、副标题、主操作区域位置统一
- [ ] 页面首屏没有明显空洞、塌陷或视觉重心失衡
- [ ] 页面主要信息区与辅助信息区层级明确
- [ ] 页面没有出现多个视觉上同等重要、但语义上主次不清的模块

### 1.2 视觉一致性

- [ ] 页面已接入统一页头结构，而不是单独拼装标题区
- [ ] 按钮样式、卡片样式、表单样式与全站最新规范一致
- [ ] 圆角、边框、阴影、间距没有明显偏离系统风格
- [ ] 字号层级清晰，没有出现标题像正文、正文像说明文字的情况
- [ ] 页面未混入明显旧版样式导致的割裂感

### 1.3 交互清晰度

- [ ] 页面主操作可直接看到，不依赖 hover 才发现
- [ ] 关键操作不会被埋在三点菜单深处
- [ ] 用户完成主要任务路径时不需要重复跳转
- [ ] 列表页、表单页、详情页都能明确看出下一步该做什么
- [ ] 加载中、成功、失败、空状态都有明确反馈

### 1.4 中文文案与本地化

- [ ] 按钮文案优先使用动作词，如“创建项目”“导入数据”“保存修改”
- [ ] 状态文案使用短语且统一，如“未开始”“进行中”“已完成”
- [ ] 空状态文案不仅描述现状，还能给出下一步建议
- [ ] 错误提示说明“为什么失败”和“建议怎么做”
- [ ] 日期时间格式默认符合中国大陆后台产品习惯，如 `YYYY-MM-DD HH:mm`

### 1.5 响应式与布局稳定性

- [ ] 常见桌面宽度下布局稳定，不会发生主区域挤压变形
- [ ] 中等宽度屏幕下不会出现关键按钮换行错乱
- [ ] 页面滚动区域清晰，不会出现多层滚动互相干扰
- [ ] 表格、筛选栏、页头在缩窄时仍能保持可用
- [ ] 弹窗、抽屉、步骤页在较小窗口下不会超出可视区域

### 1.6 可维护性

- [ ] 页面优先复用了 `web/libs/ui` 通用能力
- [ ] 页面没有新增明显重复组件
- [ ] 页面级 SCSS 没有重新定义已经存在于设计系统中的按钮、标题、卡片样式
- [ ] 页面结构拆分合理，业务容器和展示组件边界清晰
- [ ] 旧样式和新样式混用范围可控

## 2. 工作台首页验收 Checklist

适用页面：

- `web/apps/labelstudio/src/pages/Home/HomePage.tsx`

### 2.1 首屏结构

- [ ] 页面标题明确为“工作台”或同等语义入口
- [ ] 首屏能同时看到概览数据和快捷操作
- [ ] 页面右侧区块不为空，视觉重心稳定
- [ ] 页面不再只是欢迎语加少量操作

### 2.2 概览区

- [ ] 概览卡字段对用户有直接价值，如项目数、任务数、近 7 日提交量
- [ ] 统计数字展示醒目，但没有过度装饰
- [ ] 数据为空时表现正常，不会显示 `undefined`、`NaN` 或异常空白
- [ ] 概览卡顺序符合用户关注优先级

### 2.3 快捷操作区

- [ ] 至少包含“新建项目”“导入数据”等高频动作
- [ ] 快捷操作按钮文案明确，不使用模糊表达
- [ ] 快捷操作点击后路径明确，不会让用户进入歧义状态
- [ ] 快捷操作区数量控制合理，不造成选择负担

### 2.4 最近项目区

- [ ] 最近项目列表展示状态、进度、更新时间等核心信息
- [ ] 用户可直接进入数据管理或标注场景
- [ ] 没有项目时空状态明确，并附带新建项目入口
- [ ] 项目卡/项目列表信息密度适合工作台，而不是过度留白

### 2.5 系统通知与帮助区

- [ ] 右侧区块展示版本更新、帮助、新手引导等实用内容
- [ ] 不展示与用户当前工作无关的低优先级信息
- [ ] 帮助入口文案符合中国大陆用户理解习惯

## 3. 项目列表页验收 Checklist

适用页面：

- `web/apps/labelstudio/src/pages/Projects/Projects.jsx`
- `web/apps/labelstudio/src/pages/Projects/ProjectsList.jsx`

### 3.1 页面定位

- [ ] 页面定位明确为“项目管理中心”，而不是单纯项目浏览页
- [ ] 页面右上角主操作为“新建项目”或同等主动作
- [ ] 标题区与筛选区职责清晰，不互相混杂

### 3.2 筛选与搜索

- [ ] 支持项目搜索
- [ ] 支持状态筛选
- [ ] 支持负责人或成员筛选
- [ ] 支持排序，如按更新时间排序
- [ ] 筛选项排列符合高频使用顺序

### 3.3 表格视图

- [ ] 默认视图为表格，符合中国大陆后台用户习惯
- [ ] 表头字段完整且顺序合理
- [ ] 进度列同时提供数值和可视化反馈
- [ ] 操作列主次清晰，主操作不被埋没
- [ ] 行高、列宽、密度适中，便于连续浏览

### 3.4 卡片视图

- [ ] 卡片视图作为补充而不是默认
- [ ] 卡片信息足够紧凑，不出现大面积无效留白
- [ ] 卡片上的主要操作可直接触达

### 3.5 批量操作

- [ ] 支持多选
- [ ] 批量操作入口可见
- [ ] 批量操作文案明确，不产生误操作歧义
- [ ] 高风险批量操作有二次确认

### 3.6 空状态与异常状态

- [ ] 搜索无结果时有明确提示
- [ ] 无项目时有清晰空状态和主操作
- [ ] 列表加载失败时可重试

## 4. 创建项目页验收 Checklist

适用页面：

- `web/apps/labelstudio/src/pages/CreateProject/*`

### 4.1 流程清晰度

- [ ] 页面明确显示 4 步流程或同等清晰步骤结构
- [ ] 用户始终知道当前处于第几步
- [ ] 用户能够清楚知道下一步是什么
- [ ] “取消”“上一步”“下一步”“创建项目”职责清晰

### 4.2 基本信息步骤

- [ ] 项目名称等必填项明确标注
- [ ] 校验错误在字段附近提示，不只在顶部统一报错
- [ ] 表单标签、说明文字、输入框间距一致
- [ ] 中文字段命名符合中国大陆用户习惯

### 4.3 导入数据步骤

- [ ] 支持清楚区分上传方式
- [ ] 上传状态有进度反馈
- [ ] 导入结束后能显示成功数和失败数
- [ ] 导入失败时给出下一步建议
- [ ] 示例数据入口不会干扰主路径

### 4.4 标注模板步骤

- [ ] 推荐模板清晰可见
- [ ] 自定义模板入口明确
- [ ] 预览能力可用，用户不需要纯靠想象理解配置
- [ ] 模板说明语言清楚，避免纯技术化表述

### 4.5 确认创建步骤

- [ ] 能看到项目信息摘要
- [ ] 能看到导入数据摘要
- [ ] 能看到模板摘要
- [ ] 创建成功后的去向清晰

### 4.6 流程完整性

- [ ] 刷新、返回、关闭时草稿处理逻辑合理
- [ ] 不会出现步骤状态丢失但界面无提示的情况
- [ ] 操作失败时不会让用户误以为已经创建成功

## 8. 本地化专项验收项

以下项适用于所有高频页面，必须额外检查。

### 8.1 文案习惯

- [ ] 没有出现明显生硬的直译式中文
- [ ] 没有出现“查看详情”“立即开始”这类过泛、过营销化的表达滥用
- [ ] 后台操作优先使用“新建”“导入”“保存”“删除”“提交”等高频动作词
- [ ] 状态标签控制在 2 到 4 字范围内，便于表格和状态芯片展示

### 8.2 后台使用习惯

- [ ] 高信息密度页面默认优先表格，而不是卡片
- [ ] 主操作放在右上角或明显区域，而不是埋在浮层中
- [ ] 高风险操作均有显著提示
- [ ] 列表和表单更偏效率，而非装饰性

### 8.3 时间与数字展示

- [ ] 时间格式符合中国大陆用户习惯
- [ ] 大数字和百分比显示清晰
- [ ] 数字不会因为中英文字体混排产生错位

## 9. 提测前快速检查项

如果时间有限，至少完成以下快速检查：

- [ ] 页面标题和主操作是否清楚
- [ ] 首屏是否能理解页面用途
- [ ] 空状态、错误状态、加载状态是否完整
- [ ] 中文文案是否自然
- [ ] 主路径操作是否比旧版更短
- [ ] 页面是否优先复用了 `web/libs/ui` 能力
- [ ] 是否减少了旧版页面样式的割裂感

## 10. 建议的验收输出格式

建议每次页面验收记录以下内容：

- 页面名称
- 验收版本
- 验收人
- 验收日期
- 通用项结论
- 专项项结论
- 问题清单
- 是否允许进入下一轮联调或提测

建议问题等级：

- `S1`：阻塞上线
- `S2`：影响核心体验
- `S3`：建议优化
